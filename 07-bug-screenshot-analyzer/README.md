# Bug Screenshot Analyzer

Анализатор скриншотов ошибок с использованием vision-модели. Описывает проблему, классифицирует её и предлагает шаги решения. Доступен как CLI-инструмент и Telegram-бот.

## Возможности

- Анализ скриншотов ошибок из терминала, IDE, браузера
- Автоматическая классификация типа ошибки
- Описание проблемы и возможных причин
- Пошаговые инструкции по решению
- Рекомендации по предотвращению
- CLI-интерфейс и Telegram-бот
- Поддержка различных форматов изображений
- Экспорт в text, markdown, JSON

## Установка

1. Клонируйте репозиторий или скопируйте файлы

2. Установите зависимости:
```bash
pip install -r requirements.txt
```

3. Создайте файл `.env` на основе `.env.example`:
```bash
# Linux/Mac
cp .env.example .env

# Windows (PowerShell)
Copy-Item .env.example .env

# Windows (CMD)
copy .env.example .env
```

4. Откройте `.env` и добавьте ваши API ключи:
```
GEMINI_API_KEY=your_gemini_api_key_here
TELEGRAM_BOT_TOKEN=your_telegram_bot_token_here
```

Альтернативно, можно установить переменные окружения:
```bash
# Для CLI-инструмента
export GEMINI_API_KEY=your_gemini_api_key_here

# Для Telegram-бота (дополнительно)
export TELEGRAM_BOT_TOKEN=your_telegram_bot_token_here

# Windows (PowerShell)
$env:GEMINI_API_KEY="your_gemini_api_key_here"
$env:TELEGRAM_BOT_TOKEN="your_telegram_bot_token_here"
```

## Получение API ключей

### Gemini API Key
1. Перейдите на https://aistudio.google.com
2. Войдите с помощью Google аккаунта
3. Нажмите "Get API Key"
4. Создайте новый ключ и скопируйте его

### Telegram Bot Token
1. Откройте Telegram и найдите @BotFather
2. Отправьте команду `/newbot`
3. Следуйте инструкциям для создания бота
4. Скопируйте полученный токен

## Использование

### CLI-инструмент

#### Базовое использование

```bash
# Анализ скриншота
python analyze-bug.py error.png

# С дополнительным контекстом
python analyze-bug.py screenshot.jpg --context "Ошибка при запуске приложения"
```

#### Форматы вывода

```bash
# Markdown формат
python analyze-bug.py bug.png --format markdown

# JSON формат
python analyze-bug.py error.png --format json

# Сохранить в файл
python analyze-bug.py bug.png --format markdown --output report.md
```

### Telegram-бот

```bash
# Запуск бота
python telegram-bot.py
```

Затем в Telegram:
1. Найдите вашего бота
2. Отправьте `/start`
3. Отправьте скриншот ошибки
4. Получите анализ

## Примеры

### Пример 1: Ошибка Python

**Скриншот:** Терминал с ошибкой `NameError: name 'x' is not defined`

**Команда:**
```bash
python analyze-bug.py python_error.png
```

**Результат:**
```
======================================================================
АНАЛИЗ СКРИНШОТА ОШИБКИ
======================================================================

Файл: python_error.png
Категория: syntax_error

----------------------------------------------------------------------

## Описание проблемы
На скриншоте видна ошибка Python: NameError: name 'x' is not defined
в файле script.py на строке 15.

## Категория
syntax_error

## Детали ошибки
Ошибка возникает при попытке использовать переменную 'x', которая
не была определена до этого момента. Это классическая ошибка области
видимости или опечатки в имени переменной.

## Возможные причины
1. Переменная 'x' не была объявлена перед использованием
2. Опечатка в имени переменной (например, должно быть 'X' или 'x_value')
3. Переменная определена в другой области видимости
4. Код выполняется не в том порядке

## Шаги решения
1. Проверьте, что переменная 'x' объявлена до строки 15
2. Убедитесь в правильности написания имени переменной
3. Если переменная должна быть глобальной, используйте 'global x'
4. Добавьте инициализацию: x = some_value перед использованием

## Дополнительные рекомендации
- Используйте линтеры (pylint, flake8) для раннего обнаружения таких ошибок
- Следуйте принципу: объявляйте переменные перед использованием
- Используйте осмысленные имена переменных для избежания опечаток

======================================================================
```

### Пример 2: JavaScript ошибка в браузере

**Скриншот:** Console браузера с ошибкой `Uncaught TypeError: Cannot read property 'map' of undefined`

**Команда:**
```bash
python analyze-bug.py js_error.png --context "Ошибка при загрузке списка пользователей" --format markdown --output report.md
```

**Результат (report.md):**
```markdown
# Анализ скриншота ошибки

**Файл:** `js_error.png`

**Категория:** `runtime_error`

---

## Описание проблемы
В консоли браузера видна ошибка JavaScript: "Uncaught TypeError: Cannot read 
property 'map' of undefined". Ошибка возникает при попытке вызвать метод map() 
на undefined значении.

## Категория
runtime_error

## Детали ошибки
Контекст: Ошибка при загрузке списка пользователей
Ошибка указывает на то, что переменная, на которой вызывается метод map(), 
имеет значение undefined вместо ожидаемого массива.

## Возможные причины
1. API запрос не вернул данные (ошибка сети)
2. Структура ответа от API отличается от ожидаемой
3. Асинхронная операция еще не завершилась
4. Неправильная обработка ошибок в цепочке промисов

## Шаги решения
1. Добавьте проверку на существование данных:
   ```javascript
   const users = data?.users || [];
   users.map(user => ...)
   ```

2. Проверьте ответ от API в Network tab браузера

3. Добавьте обработку ошибок:
   ```javascript
   fetch('/api/users')
     .then(res => res.json())
     .then(data => {
       if (data && data.users) {
         data.users.map(...)
       }
     })
     .catch(err => console.error(err))
   ```

4. Используйте optional chaining и default values

## Дополнительные рекомендации
- Всегда проверяйте данные перед использованием методов массива
- Используйте TypeScript для статической типизации
- Добавьте fallback UI для случаев отсутствия данных
- Логируйте ответы API для отладки
```

## Категории ошибок

Инструмент автоматически классифицирует ошибки:

- `syntax_error` - Синтаксические ошибки в коде
- `runtime_error` - Ошибки времени выполнения
- `network_error` - Сетевые ошибки (404, 500, timeout)
- `ui_bug` - Проблемы с интерфейсом
- `configuration_error` - Ошибки конфигурации
- `dependency_error` - Проблемы с зависимостями
- `permission_error` - Ошибки доступа
- `database_error` - Ошибки БД
- `other` - Другие типы ошибок

## Технические детали

- **Vision модель**: Google Gemini 2.5 Flash (с поддержкой изображений)
- **Поддерживаемые форматы**: PNG, JPG, JPEG, GIF, BMP, WEBP
- **Максимальный размер**: Ограничен API (обычно до 20MB)
- **Время анализа**: 10-30 секунд

## Ограничения

- Google AI Studio (Gemini): ~1500 запросов/день
- Качество анализа зависит от четкости скриншота
- Текст ошибки должен быть читаемым
- Лучше работает с англоязычными ошибками
- Не заменяет глубокую отладку

## Рекомендации

### Для лучших результатов

1. **Четкий скриншот**: Убедитесь, что текст читаем
2. **Полный контекст**: Захватите всю ошибку, включая stack trace
3. **Добавьте описание**: Укажите, что вы пытались сделать
4. **Увеличьте шрифт**: Если текст мелкий, увеличьте перед скриншотом

### Что включать в скриншот

- ✓ Полный текст ошибки
- ✓ Stack trace (если есть)
- ✓ Номер строки и файл
- ✓ Контекст кода (если виден)
- ✗ Не обрезайте важную информацию
- ✗ Избегайте размытых изображений

## Безопасность

- Не отправляйте скриншоты с конфиденциальной информацией
- Замазывайте API ключи, токены, пароли
- Скрывайте личные данные пользователей
- Проверяйте скриншоты перед отправкой
